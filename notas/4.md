## TL;DR
- Sharing today is built around **live sessions**. You can share a file **Online** (it goes to a figcraft-server, by default `wss://collab.craftapps.dev/`, which hands out an edit link and a view link plus 9-symbol join codes). You can share on the **Local network** (the app hosts the session). Or you can use **Publish to server…**. Every link is a `figcraft://join?...` URL.
- No **Share prototype** feature exists, and the presenter has no share button. `docs/prototyping-parity.md:97` says so: `| Share a prototype link | missing | needs multiplayer/sharing |`.
- **View-only joins exist** (`Access::View`, view links and view codes) and are enforced on the client and the server. A viewer opens the **whole file in an editor tab**, though, not the presenter. No link format carries a node or flow id.
- A **snapshot publish that is not live** exists in the network layer (`LiveLink::upload`, `Admin::Publish`). Only `library.publishToServer` uses it, and `NetLink::upload` requires the server key. No request replaces the content of an existing server file.
- **The browser cannot open a link today.** `figcraft://` is a desktop-only scheme. The web build (`apps/figcraft-web`) reads nothing but `?webgl` from its URL. In the web build, **Copy link does nothing** because `WebServices` doesn't implement `clipboard_set_text`. Nothing in the code calls `ctx.copy_text`.

## 2. How a file gets published and gets a code or link
**Online share** (the main path): the popover's Start sharing runs `collab.share {via:"online"}`.
1. `crates/engine/src/live.rs:1646-1700` reads the server from `prefs.publish_server` (default `DEFAULT_SERVER` at `live.rs:66-71`, overridable at build time with `FIGCRAFT_DEFAULT_SERVER`), then calls `start_publish(..., share=true)` (`:1631-1643`).
2. `start_publish` calls `LiveLink::publish`, which is `NetLink::publish` (`crates/collab-net/src/link.rs:~180-187`), then `Guest::publish`.
3. `upload_file` (`crates/collab-net/src/guest.rs:177-205`) takes `Replica::new(doc).snapshot()` and sends `Admin::Publish {name, snapshot}`:
   - with the server key, on a `Manage` connection;
   - without it, on an `OpenHosting` connection, for a server open to the public.
4. The server answers `AdminReply::Published` or `AdminReply::Hosted {owner, expires}`, carrying an edit token and a view token. The app joins with the edit link, and its tab stays in sync with the server.
5. `manage::share` (`crates/collab-net/src/manage.rs:105-150`) sends `CreateLink` for edit and for view, then `Admin::Code` for each link. The result is `Shared {edit: SharedLink{id, link, code}, view: Some(..)}` (`engine live.rs:205-223`), delivered as `Event::Shared`.
6. The UI shows the code for the selected access (`Share::shown/code/link`, `live.rs:242-256`).
7. Files published without the server key are recorded with the owner token in `prefs.online_files` (`crates/engine/src/online.rs:48-70`).

**Publish to server…**: `collab.publish {server, name}` (`live.rs:1622-1626`). It produces edit and view links plus an owner token, but no codes.

**Local network**: `collab.share {via:"local"}` calls `start_host(Bind::Lan, short=true)` (`live.rs:1604-1620`). The code is a 20-symbol `code::Local` that encodes IPv4, port and secret (`crates/collab/src/code.rs:7-11`). Local shares can't be view-only (`LOCAL_EDITS`, `live.rs:1644`).

## 3. What the links look like
All formats are documented in `crates/collab-net/src/invite.rs:3-16` and built at `:116-127`.

| Kind | Format | Where built |
|---|---|---|
| Desktop-hosted session (plain `ws://` at `/`) | `figcraft://join?host=<ip:port>&file=<id>&token=<secret>` | `invite.rs:116-127` |
| Server file (any endpoint) | `figcraft://join?server=<ws(s)://host:port/path/>&file=<id>&token=<secret>` | `invite.rs:116-127` |
| Same session as a raw WebSocket URL | `ws(s)://host:port/path?file=<id>&token=<secret>` | `Invite::url` |
| Online join code | `figcraft://join?server=<server>&code=<9 symbols>` | `engine live.rs:258-270` |
| Local code | `figcraft://join?host=<ip>:<port>&file=local&token=local-<11 hex>` | `collab/src/code.rs:128-130` |

- Online codes are shown grouped as `K7M-2QX-9TD` (`code.rs:69-73`).
- With the default server, a server link reads like `figcraft://join?server=wss://collab.craftapps.dev:443/&file=…&token=…`, because `Endpoint::parse` adds the port (`invite.rs:94`). The server URL is not percent-encoded inside the query.
- **Parsing tolerates extra query keys.** `Invite::parse_join` (`invite.rs:149-182`) reads only `server`, `host`, `code`, `file` and `token`. `code::Local::from_link` uses `find` (`code.rs:133-139`). So `&node-id=…&starting-point-node-id=…` could be appended without breaking old clients.
- The path must be `join` (`invite.rs:157`). A new path such as `figcraft://proto?…` would be rejected.
- Tokens never travel in the WebSocket request URL; they go in the `Hello` (`invite.rs:9-12`).

## 4. The URL scheme handler
- **Command line.** `apps/figcraft/src/args.rs:1-2, 17-19`: `is_invite` treats any argument starting with `figcraft:` as an invite. `apps/figcraft/src/main.rs:163-165` passes it to `figcraft_ui_egui::live::open_invite` (`ui live.rs:1036-1041`), which runs `collab.join {link}`. If that fails, the Join dialog opens with the link in it.
- **Registration per platform:**
  - Windows registers per user at run time under `HKCU\Software\Classes\figcraft` (`crates/collab-net/src/links.rs:1-60`, `crates/engine/src/invite_links.rs`). The preference defaults to on for installed builds; it is set up in `main.rs:150-152`.
  - macOS declares the scheme with `CFBundleURLTypes` in `packaging/macos/Info.plist.in:73-84`.
  - Linux declares it in the desktop entry: `x-scheme-handler/figcraft` (`packaging/linux/ai.storyteller.figcraft.desktop:14`).
- **Gaps:**
  - I found no Apple Event (`kAEGetURL`) handler in `apps/figcraft/src`, and macOS delivers URL opens that way, not through argv. Worth verifying on a Mac.
  - There is no single-instance forwarding: each link starts a new process.
  - `figcraft://node/` and `figcraft://comment/` links would also go to `collab.join` and fail.
- **Browser.** `apps/figcraft-web/src/web.rs:24-28, 57-59` reads only `?webgl` from `location.search`. Nothing joins from the page URL. The web build starts with one new document (`apps/figcraft-web/src/main.rs:9`).

## 5. How the desktop app talks to the server
- **Layering.** The engine defines `trait LiveLink` (`crates/engine/src/live.rs:446-527`) and never opens a socket (`live.rs:5-8`). The app installs `figcraft_collab_net::NetLink`:
  - natively, `crates/collab-net/src/link.rs`: blocking `tungstenite` 0.30 with a reader and a writer thread per connection, and `rustls` (ring, webpki-roots) for `wss://` (`crates/collab-net/Cargo.toml`);
  - in the browser, `crates/collab-net/src/web.rs`, over `web_sys::WebSocket`. It refuses `ws://` from an https page (`web.rs:170-173`).
- **Engine commands:** `collab.host`, `collab.share`, `collab.stop`, `collab.join`, `collab.leave`, `collab.publish`, `collab.serverInfo`, `collab.manageFile`, `collab.files`, `collab.openFile`, `collab.forgetFile`, `collab.peers`, `collab.report`, and others (specs around `live.rs:1925-1995`).
- **Wire format:** one version byte (`WIRE_VERSION=1`) followed by postcard, or a JSON form for debugging (`crates/collab/src/message.rs:1-2, 703-750`). `PROTOCOL=2` (`:13`).
- **First message on a connection:**
  - `Hello {file, token, name, color, client_version, resume}` (`message.rs:43-57`) to join;
  - or `Manage {key}`, `OpenHosting {file, owner}`, `Resolve {code}`, `OpenLibrary` or `OpenPlugins`.
- **Admin requests** (`message.rs:242-277`): `Publish {name, snapshot}`, `Files`, `Links`, `CreateLink {file, access, label}`, `Revoke`, `Remove`, `Rename`, `Code {file, token}`, `Owned`, plus the moderation requests.
- **Server messages** (`message.rs:630-695`): `Welcome {session, client_id, seq, catch_up, processed, peers, access}`, `Changes`, `Reject`, `Presence`, `PeerJoined`, `PeerLeft`, `Refused`, `Admin(..)`, `Hosting(HostInfo)`, `Resolved {file, token}`, and others.
- The server speaks only WebSocket, plus `GET /healthz` (`crates/collab-net/src/hub.rs:21-22, 684-709`). It does not serve the web app or any HTML.

## 6. View-only (read-only) join
Yes, it exists.
- `Access::{Edit, View}` (`message.rs:58-87`). Every server file gets a view link (`manage.rs:119-121`), and online sharing gets a view code. The popover's "Can view" shows the view code (`ui live.rs:879-890`).
- **Client enforcement:**
  - on Welcome with `Access::View`, the tool is forced to Move (`engine live.rs:1199-1202`);
  - `live_read_only` and `active_read_only` (`live.rs:1230-1243`) feed `begin_interaction` (`crates/engine/src/lib.rs:950-952`) and the tool switching (`cmd/view.rs:169`);
  - the UI shows "View only" and VIEW_NOTE (`ui live.rs:39, 917-920`).
- The server refuses a viewer's batches (`message.rs:58-60`).
- Presenting is not an edit (`proto.present` has history=false, `cmd/proto.rs:116-122`), so a viewer can present.
- **Caveats for "Anyone can view":**
  - the viewer gets the **entire file** in an editor tab (`live.rs:1190-1195`, "Joined {name}"), not the presenter;
  - every viewer joins the owner's live session as a peer with cursor and presence;
  - the session cap is `max_peers` 256 by default (`crates/collab/src/lib.rs:101`), or `max_people` on the server (`apps/figcraft-server/src/config.rs:266`).

## 7. Can the client publish a snapshot that is not live?
Partly.
- `LiveLink::upload` / `NetRequest::Upload(PublishOptions)` (`engine live.rs:336-338, 467-473`) keeps a document on a server as a new file without joining it.
- `NetLink::upload` (`collab-net link.rs:189-191, 276-281`) **requires the server key** ("the server address needs the server's key…"). The lower-level `upload_file` (`guest.rs:177-205`) already supports publishing without a key on a server open to the public (`manage::hosting`, which returns an owner token).
- The only caller is `library.publishToServer` (`crates/engine/src/cmd/library.rs:354-372`).
- `Admin` has no request to replace a file's content (`message.rs:242-277`), so every snapshot publish creates a **new** file with new links.
- A published file is still a normal live document: edit-link holders can change it, and view-link holders only watch.

## 8. Clipboard
- Everything copies through `Services::clipboard_set_text` (`crates/ui-egui/src/lib.rs:166-178`, a no-op by default).
- Desktop: `arboard` (`apps/figcraft/src/services.rs:12, 56, 207-211`).
- Web: `WebServices` (`apps/figcraft-web/src/web.rs:72-110`) overrides only `open_url`, `reduce_motion`, `system_language` and `gamepad_held`. **`clipboard_set_text` stays a no-op**, so Copy link and Copy code copy nothing in the browser, while the toast still says "Invite link copied".
- There are **no `ctx.copy_text` calls** anywhere in the repo. The workspace uses egui 0.36 (`Cargo.toml:74`), which has `Context::copy_text(String)`, a reasonable web fallback.
- Toasts come from `app.toast(...)` (`lib.rs:620-622`). They also show while presenting (`lib.rs:987-991` calls `toast_ui`).

## 9. Flows and starting points (what a share link must target)
- **Model:** `Flow {name, start: NodeId, description}` (`crates/doc/src/proto.rs:771-778`), stored per page in `NodeKind::Page { flows, .. }` (`crates/doc/src/node.rs:73`).
- **Commands:** `proto.flow.add`, `proto.flow.rename` and `proto.flow.remove` (`crates/engine/src/cmd/proto.rs:55-110`).
- **Prototype tab UI:** "Flow starting points" rows with Present this flow, Preview and Remove (`crates/ui-egui/src/proto_panel.rs:343-372`). There is no "Copy link" on a flow.
- **Presenting:**
  - `proto.present {start?}` (`cmd/proto.rs:116-122`) goes to `open_player` (`:258-280`).
  - The start defaults to the selected top-level frame, then the page's first flow, then its first frame. It sends `request_ui("present", {start})`.
  - The UI handles that at `crates/ui-egui/src/lib.rs:686-692` with `present::Presenter::new(start)`.
  - `Presenter.start` is private (`present.rs:257`); `current` is public (`:248`).
  - The bar's flow picker matches `f.start == p.start` and switches with `p.restart(f.start, now)` (`present.rs:2117-2155`, `restart` at `:663`).
- **There is no parameter to open at a node other than the starting point.** A Figma-style `node-id` (the current frame) plus `starting-point-node-id` (the flow) needs a new `proto.present` parameter, or a jump inside the Presenter.
- **Node ids survive syncing.** `Change::Create { id, .. }` carries the id (`crates/collab/src/change.rs:63`), and `Replica::snapshot` and `from_snapshot` replay creates (`crates/collab/src/replica.rs:74-97`). A node id in a link therefore names the same node in the viewer's copy.

## 10. Where a "Share prototype" dialog can reuse existing pieces
- **Backend: get a view link.**
  - Call `collab.share {via:"online", access:"view"}` through `app.run_background(ctx, "collab.share", …)`, as `private_ui` does at `ui live.rs:780-782`.
  - Read `app.session.live().share` and use `Share::link()` / `code()` (`engine live.rs:242-256`), or `share.links.view.link` and `.code`.
  - If the file is already shared, the same call with `access` only switches which link is shown (`live.rs:1660-1677`).
  - `collab.peers` exposes `share.viewLink` and `share.viewCode` (`live.rs:1995`).
- **"Who has access: Anyone can view":** reuse the strings and logic at `ui live.rs:879-890` (Can edit / Can view segment, "Anyone with this code can look at the file…"), plus `host_line`, `expiry_line` and `hosting_lines` (`:619-627, 945-970`) for the server's terms and expiry.
- **Copy rows:** `link_rows` (`ui live.rs:1010-1027`) gives label, elided monospace value and a Copy button with a toast. The dialog frame is `crate::dialogs::window(title, ctx)` (`dialogs.rs:19-21`).
- **Constraints inside the presenter:**
  - `FigApp::ui` returns early while presenting and **does not call `dialogs::show`** (`lib.rs:987-991`). The dialog must be drawn from `present::show` (`present.rs:1629-1685`), with a new `BarAction` (`:1612-1627`) and a button in `top_bar` (`:2067-2083`).
  - Escape closes the presenter (`present.rs:1682`), so the dialog must consume Escape first.
  - **F** already toggles fullscreen through `ViewportCommand::Fullscreen` (`:1659-1662`); a fullscreen button can reuse that.
  - `view.toggleUi` is already bound to `Cmd+\` in the editor keymap (`crates/engine/src/keymap.rs:164`), but the presenter doesn't handle it.
  - The scaling options live in `options_menu` and `PresentScale` (`present.rs:2160`, `:138`).
- **Opening the link into the presenter.**
  1. Append `node-id` / `starting-point-node-id`, or a `present=` key, to the `figcraft://join?…` view link. Old parsers ignore it.
  2. In `open_invite` (`ui live.rs:1036-1041`), remember the start for that join's `SessionId`.
  3. When the session starts syncing (the same check `home.rs:274-283` `opened_join` uses: `Live::syncing`), run `proto.present {start}` on the new tab.
- **Making it openable in a browser:**
  1. Host the `figcraft-web` static build somewhere. No hosted URL exists in the code; only the help link `https://getartcraft.com/apps/figcraft` (`lib.rs:720`). `packaging/web/README.md` covers self-hosting.
  2. Have `figcraft-web` read the invite from `location.hash`. The hash keeps the token out of server logs, matching the rule at `invite.rs:9-10`. Then call `open_invite`.
  3. Implement `WebServices::clipboard_set_text`, for example with `ctx.copy_text`.
  4. Use a `wss://` server. The default `wss://collab.craftapps.dev/` already is one, which `web.rs:170-173` requires on https pages.
  5. The share URL would then look like `https://<web-host>/#join=<urlencoded figcraft://join?server=…&file=…&token=…>&node-id=…&starting-point-node-id=…`.
- **Not present at all:**
  - "Get embed code": nothing exists. It would be an `<iframe src="https://<web-host>/#…">` built from the same URL.
  - "Invite by email": nothing exists. There are no accounts and no mail; the closest thing is `services.open_url("mailto:…")` (`lib.rs:188`).
  - A "Share prototype" entry point.
